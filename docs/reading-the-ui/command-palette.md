## Command palette

- **Command palette**: the **Commands** button of the top bar (a magnifier, with its name from 640 px wide; kept in the folded bar from 768 to 1023 px, not drawn under 768 px wide, where the folded bar has no room for it), or Ctrl+K (Cmd+K on a Mac), opens a search over five groups: *Actions* (play / pause, zoom to fit, full screen, hex grid, mute, the shortcuts dialog, settings, and the commands below that the view can run now), *Panels* (each panel, same names as the top bar; the Files & repeats panel is also found by "waste" or "repeated", for its *Repeated reads and calls* section), *Sessions* (including "All sessions"), *Agents* (the agents the Sessions panel lists, so finished agents hidden by "Hide inactive" are not offered) and *Themes* ("Theme: <name>" for each theme of Settings > Appearance, the one in use marked "current theme"). Type to filter (every word must match), Up / Down to move, Enter to run, Escape to close; focus returns to where it was. It is a modifier combination, so it works even with single-key shortcuts turned off, and from a text field, but not from inside another dialog. Only recorded facts are shown next to a name:
  - a session: runtime, project, branch, "current view", and "finished" only when the session list says it completed (or "imported - not live" / "indexed - not observed", as in the Sessions panel). It is never called active or running: nothing the palette reads proves that;
  - an agent: its role (Main, Subagent, Teammate) and its session, never its state, which may be older than the screen;
  - a shortcut next to a command is shown only while it works (none for single-key shortcuts when they are off);
  - some actions are listed only while they can run: "Go to the next agent that needs you" (first, with the text of the attention counter as its only detail) while an agent waits for a permission or failed; "Export this session as an HTML replay" while the session of the view has events in memory (not in the demo or a view that groups sessions); "Turn notifications on" / "off" while the browser allows them; the tour of the legend, under the same name ("Tour this session", or "Guided tour" in the demo), while one can start. While the relay serving the page accepts launches ([launch-security.md](../launch-security.md)), "Find issues to launch for agent:<role>" (found by "launch") is listed once per role and session of the agents the view lists: it opens the card of the first agent bearing that role (named in its detail), where the open issues with that label have their **Launch** button and its confirmation. The entry does not say that such an issue exists: the card says so once it has read them. "Toggle presentation mode" and "Clear history" (undone like from the control bar, with the Undo of its notification) are always listed.

  Each group shows at most 8 matches, and the status line below the list says how many more there are ("keep typing to narrow") instead of pretending the list is complete. Session and agent names (and their details) carry `data-sensitive`, so presentation mode blurs them like in the other panels. Agents of another session are offered only while the view contains them: select that session (or "All sessions") first.

### In your language

- the command palette (its title, search field, group names, commands and their descriptions, details such as "current view" or "finished", the result count and the key hint). The panels are named *Fichiers et répétitions*, *Conversation*, *Contexte*, *Système*, *Coût*, *Chronologie* and *Statistiques*. The titles of the panels that have one follow the same names (see the panel titles in [Panels](panels.md#in-your-language)). A command is found by its French name or by its English name ("full screen" finds *Basculer en plein écran*), and accents are optional when typing. Names of sessions and agents, branches and projects are data and stay as they came. The legend is described in [Graph legend and guided tour](legend-and-tour.md#in-your-language).
