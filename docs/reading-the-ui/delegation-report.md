## Delegation report

When the selected agent has sub-agents, its inspector ends with a **Delegation report** (#233): one entry per direct sub-agent (a grandchild is in the report of its own parent; Agent Team teammates are not delegations and are not listed), in the order they started. The sub-agent name is a button: Enter or a click opens that sub-agent's own inspector. The list of files read is a disclosure (Enter or Space opens it).

| Column | You see | It means |
| --- | --- | --- |
| **Tokens** | `12k`, **at least X**, **estimated**, **not reported** | The sub-agent's own token counter, qualified as everywhere else. |
| **Files read** | **N files** | Distinct files whose `Read` by this sub-agent was observed to succeed. The disclosure lists them (20 at most, then "+N more"). |
| | **N not confirmed** | Files whose `Read` started but was never seen to succeed (failed, cancelled, still running or end not observed). They are not counted as read. |
| | **none observed** | No `Read` by this sub-agent was received. It is not shown as "0 files": reads through other tools (Bash `cat`, Grep) are not seen. |
| **Duration** | **m:ss (measured)** | Measured by Agent Lens (the relay or the extension) between the dispatch and the return it observed live. It is not a figure the runtime reports with every return. |
| | **m:ss (recorded)** | A background sub-agent whose completion notice records its own duration: that recorded figure, not a measurement by Agent Lens. |
| | **not reported** | A return was received without a duration, or it came from a history replay or an imported transcript: there the duration was measured when the line was parsed, not while the sub-agent ran, so it is dropped. |
| | **no return observed** | No return of this sub-agent was received; no duration is computed from the clock. |
| **Result** | the start of the report | The first 280 characters of what the sub-agent returned to its parent, with "…" and "(full report in Conversation)" when cut. |
| | **Error: ...** | The return was flagged as an error. |
| | **No return observed yet** / **Finished, no return observed** | No return was received, whether or not the sub-agent is known to have finished. |

A sub-agent launched in the background (Claude Code's default, and always with `isolation: "worktree"`) is not finished by its launch: the tool result its parent gets right away only says it started. It stays running until Claude Code's task notification for it says `completed` (a return) or `failed`, `killed`, `stopped` or `cancelled` (an error), with the duration that notification reports. A notification without a status (an agent restarted after Claude Code exited) or with an unknown status finishes nothing. A finished sub-agent that resumes (relaunched with `SendMessage`, "Resuming agent") becomes active again from what is observed: a tool call it starts (one not seen before) brings it back at once; an assistant or thinking message of its own does so only after the prompt it received following its end. No new spawn is needed. A prompt alone, a late result or a bookkeeping event does not bring it back, nor does a late assistant or thinking message of the turn that already ended. Known limit: the last tool call of a turn can be read after the sub-agent's end, and then shows it active again until its next end. The next end is the one Claude Code's task notification reports after the resume (the `SendMessage` result names the agent it resumed); without that notification it stays active or "between two steps" and is never shown as finished.

A sub-agent already running when the relay or the extension attaches to the session (launched before a restart of the relay, for example) is drawn from the attach on, under the name its later events use ([#446](https://github.com/j0hn-42/agent-lens/issues/446)). It is drawn only when all of this is proven: its launch is in the session's transcript, the transcript shows no end for it (no final tool result for a sub-agent run in the foreground, no `completed`, `failed`, `killed`, `stopped` or `cancelled` task notification for one in the background, or a `SendMessage` resume after that notification; its file's metadata does not say the user stopped it), and its own transcript file exists and was written in the last 10 minutes (`ACTIVE_SESSION_AGE_S`); an older one appears on its next transcript line, if its launch still shows no end. It starts idle, read from history (its status is only a last known state); its next tool call or message seen live makes it live. A sub-agent whose end is in the history is not brought back, even if its file grows; a launch without a file is not drawn. At most 16 such sub-agents per session are drawn at the attach (`SUBAGENT_CATCH_UP_SPAWNS_MAX` in `extension/src/constants.ts`), in the order of their launches; any other one appears on its next transcript line, and the relay log says how many were held back.

A sub-agent whose link to its parent is not proven by the events (dashed on the canvas) reads **parent link not verified**. When the hooks see a sub-agent stop without its report, the result is the stop notice they relay (for example "general-purpose complete"), not a report.
